# Portal 界面设计

主题来自传送枪参考图的绿色、灰色设备和圆润轮廓。导航顶部使用名称与简化几何标识，不使用原始插画。

## 配色

- 页面背景：`#F3FAF0`；正文：`#182018`。
- 主色：`#326B2D`；按钮白字对比度约 6.41:1。
- 选中容器：`#DDF7D5`；容器文字：`#163A18`。
- 深色背景：`#101A12`；主色：`#8ED27F`。
- 错误与停止操作沿用语义错误色。

Compose 默认使用绿色主题，原紫色通过 `PortalColorStyle.CLASSIC` 保留。界面暂不增加主题切换设置。

## 图标

`icons/` 保存原始 SVG，应用中的 `ic_portal_*` VectorDrawable 使用同一条路径。

- 统一 24 × 24 viewBox，描边 1.7，圆端点与圆连接。
- 图形保持比例，不拉伸；常规控件使用 24dp，品牌标识可等比放大。
- SVG 使用 `currentColor`；Android 端通过主题 tint 适配明暗模式。
- 功能图标保持单色，绿色底色由容器提供，危险色由操作语义决定。

## 导航与设置

抽屉按定位、模拟、运行、其他分组，使用圆角选中容器。品牌头部只展示 Portal、几何图标和运行状态摘要；摘要仅在状态或后端变化时更新。

设置目录包含地图与定位、运动与摇杆、卫星与 GNSS、分应用规则、系统与环境模拟、高级与实验、后台与隐私、关于与更新。分类使用独立 Fragment destination，保留返回栈与页面重建状态；持久化键和设置读写 API 不变。

“恢复并启动上次场景”位于运行页。地图与定位作为相连圆角分组的详情页样板，参数旁保留单位，组下说明生效时机。

## 第二轮：应用选择与详情分组

应用排除、固定点分配和传感器目标使用 `AppSelectionFragment`。应用列表在 IO 线程加载，支持名称/包名搜索、仅已选筛选和清空。已有但当前不可见的包名保留在列表；草稿跨 Activity 重建恢复，返回放弃修改。只有保存才发送 Fragment Result，设置页基于最新配置合并对应规则。

运动、定位通道、分应用规则、后台隐私和更新页面改为相连圆角分组，开关回调和原有能力限制保持一致。

验证：Debug 与 instrumentation APK 编译通过；小米 M2102K1C / Android 14 上的开关回归、功能入口和选择草稿/保存共 5 项测试通过，已查看带键盘的应用选择页截图。

## 第三轮：剩余设置分组与包名编辑

系统、高级设置和 GNSS 数量设置改用相连圆角分组。GNSS 策略使用整行单选，显示当前选择；选择弹窗状态支持页面重建。既有能力限制、设置键及配置回调保留。

传感器包名编辑移入独立页面，支持多行输入、完整包名校验、最多 128 个目标及草稿恢复。显式保存后才修改配置，返回放弃；保留 Xposed 与重启目标应用的说明。

## 第四轮：固定位置选择与环境入口

空白应用规则按首次使用的默认配置处理，非空且无法解析的配置仍拒绝覆盖。系统与环境模拟分类新增环境工具入口；采集、Wi-Fi 指纹与环境生成/回放改为相连圆角分组，原有采集、导入、导出、回放与权限流程保留。

## 第五轮：地图运行控制与紧凑布局

地图底部增加运行阶段、后端与当前场景摘要；运行时可直接暂停、继续和停止，准备/停止阶段禁用不适用的操作。暂停按钮使用新增的统一线性 SVG/矢量图标，并提供无障碍描述和轻量显隐过渡。

地图控件只订阅阶段、后端和场景名称，位置采样仍交给既有地图渲染链路，避免坐标更新触发控件重组。地图 SDK View 保持全尺寸，底部遮挡高度仍按实际面板测量。低高度屏幕为右侧工具栏保留独立空间，定位提示采用紧凑行。

补齐绿色主题的次级/三级容器、表面染色和反色语义，消除 Material 默认紫色在地图按钮等控件中的残留。新增文本/容器配对对比度均超过 4.5:1。

验证：Debug 与 instrumentation APK 编译通过；小米 M2102K1C / Android 14 上暂停/继续/停止及暂停后重建、原有路线/地点显式启动、全屏地图安全边距、主页面明暗主题、大字体横屏共 5 项专项测试通过。横屏完整面板边界加强后再次通过，已检查暂停与稳定横屏截图。独立 Debug 包出现地图 SDK 鉴权提示，地图瓦片效果不据此验收；实际 Xposed / Native 输出及帧率尚未验证。

后续：设置当前值与生效时机统一、环境列表交互、路线编辑反馈，以及动效和帧率测量。

## 第六轮：设置当前值与生效说明

公共设置行新增独立状态文字，开关行支持前置图标插槽，整行开关语义保持不变。定位参数、运动、定位通道、系统、高级、GNSS、应用传感器与更新通道分别标注即时更新、下次启动、运行中尝试应用或重启目标应用等时机。Hook 配置说明保留未运行/应用失败时的回退行为；不将保存偏好等同于配置已经应用。崩溃报告区分请求开启、实际开启和等待重启。

分应用规则显示排除/固定应用数量，后台解析规则，读取失败明确提示；保存固定点规则后的数量摘要随偏好变化更新。设置页只订阅后端变化，不再因定位采样而接收完整运行状态。

## 第七轮：环境资料独立列表

## 第八轮：路线反馈与真实帧耗时

路线模式说明和规划状态加入轻量淡入淡出；失败状态采用错误色并提供无障碍实时播报。清空与切换模式的确认状态跨页面重建保留，原有地图 View、草稿和保存链路保留。

新增真实时钟的窗口帧采样工具与交互测试，不使用 Compose 测试虚拟时钟。小米 M2102K1C / Android 14 的独立 Debug 包上，每组重复 4 次，结果如下：

| 操作 | 帧数 | p50 / p95 / p99（ms） | 超过系统 deadline 的帧 |
| --- | ---: | --- | ---: |
| 抽屉展开/收起 | 494 | 7.89 / 9.05 / 15.46 | 3 |
| 设置分类、数值弹窗与返回 | 385 | 6.53 / 122.88 / 246.28 | 33 |
| 路线模式切换 | 524 | 9.26 / 24.54 / 76.61 | 23 |

三组采样均未丢失回调，排除首次绘制帧，超时按各帧系统 deadline 判断。设置切换仍有明显慢帧，不能据此宣称整体流畅。此数据只覆盖应用窗口，不覆盖地图独立 Surface/GPU 的完整呈现，也不能代表 Release 性能。原始 JSON 保留在测试设备 Download/Portal-ui-frame-stats，测试可重复生成。

验证：Debug 与 instrumentation APK 编译通过，路线模式回归及真实帧采样测试通过，已检查路线反馈截图。采样 listener 清理改为幂等，避免保存后重复移除导致测试失败。

后续：检查设置切换慢帧来源，专项验证路线编辑的低高度/大字体布局，并审计完整路线图的兼容与交互覆盖。整体目标尚未完成。

## 第九轮：低高度路线编辑与采样拆分

低高度且宽度至少 600dp 时，路线编辑采用左侧可滚动控件、右侧地图的双栏布局；普通竖屏继续上下布局。小米真机 1.3 倍字体横屏检查通过：搜索与保存操作可达，地图至少保留 200dp 高、240dp 宽，转回竖屏入口正常。MapUiTest 共 4 项通过，已检查横屏截图；截图中的地图鉴权提示来自独立 Debug 签名。

将设置内部导航与地图往返拆分采样，避免把地图重建开销全部归于设置。最新 Debug 测量（各 4 次）：

| 操作 | 帧数 | p95 / p99（ms） | 超过系统 deadline 的帧 |
| --- | ---: | --- | ---: |
| 抽屉展开/收起 | 443 | 8.65 / 15.32 | 5 |
| 设置内部导航与数值弹窗 | 322 | 33.63 / 155.87 | 13 |
| 地图与设置往返 | 239 | 135.00 / 260.66 | 25 |
| 路线模式切换 | 523 | 21.53 / 84.90 | 20 |

四组均无采样回调丢失。地图往返出现更多长耗时帧，设置内部仍有慢帧；尚未通过线程追踪确定根因，不能把这次不同工作负载的数据视为性能改善幅度。此处继续沿用上一轮窗口/Debug 测量边界。

后续：结合主线程追踪定位页面切换与地图重建开销，并完成抽屉手势、后端能力状态、深链接兼容等路线图审计。整体目标继续实施，未发布正式 APK。
