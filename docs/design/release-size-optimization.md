# Release APK 体积优化记录

## 结果与口径

2026-11-17，在 `b03eb4d1` 的应用源码基础上启用 R8、资源裁剪及 Release DEX 压缩。
本地构建产物未使用正式发布签名，以下大小均按十进制 MB（1 MB = 1,000,000 bytes）计算。

| 构建 | APK 大小 |
| --- | ---: |
| 同源码 arm64 未优化基线 | 64.97 MB |
| 优化后 arm64 | 28.93 MB |
| 优化后 all（arm64 + x86_64） | 33.33 MB |
| 优化后 x86_64 | 19.66 MB |

arm64 同源码对比减少 36.04 MB（55.5%）。作为参考，已发布 v2.3.5 的
arm64 APK 为 64.28 MB；该版本与当前源码有差异，不能用来单独衡量本次优化收益。

主要收益来自代码：DEX 从 5 个、未压缩合计 39,987,468 bytes，变为
2 个、未压缩合计 11,133,232 bytes，压缩存入 APK 后为 5,097,102 bytes。
APK 下载体积减少不等于安装占用同比减少，压缩 DEX 需要安装阶段处理；本次没有进行启动性能基准测试。

## 实现范围

- 仅 Release 启用代码优化、混淆、资源裁剪和 DEX 压缩；保留原有 ABI 产品及 native 打包方式。
- 主应用显式声明 libxposed API 的 `compileOnly` 依赖，让 R8 获得框架接口层级；框架 API 不打入 APK。
- 保留 PortalModule 生命周期、Hooker 的 `intercept`、JNI 方法名及模块包名前缀。
  仅在 xposed 模块声明 `compileOnly` 无法为最终应用的 R8 提供完整类型信息，会导致回调实现被误删。
- 地图依赖、版本和功能没有调整。高德聚合 JAR 没有 consumer rules，保守保留其全部类和成员；
  腾讯沿用 AAR 自带的规则。仅忽略高德现有可选缺类的两项精确警告。
- 对比同源码 arm64 基线，全部 7 个 native 条目及 239 个普通 assets 逐字节一致；
  assets 比较不包含构建生成的 DEX profile 和自研加密 native 载荷。
- CI 新增直接解析 APK DEX 定义的检查，验证实际回调实现、JNI 定义和 DEX 压缩方式，
  并保留 R8 mapping 供崩溃还原使用。该检查区分方法引用与真正的方法定义。

## Native 实际 Hook 补测

在两机冷启动优化后的 Release 模块后，通过最终 APK 内的 `NativeBackend`
执行 prepare、start、publish、stop 和再次 start/publish/stop，实际加载并 Hook
`system_server` 中的传感器转换函数。接收端使用新建的独立包名和 UID，未加入模块作用域，
收集约 6 秒一组的公开 SensorManager 样本；确认接收端无法获得控制令牌，且 Java 传感器保护未启用。

首轮发现旧预置载荷将步数写成浮点位模式，接收端读到 `1065353216`、`1105199104`
等异常整数。现有 C++ 源码已在 `494579bf` 修复该布局，但预置 `liblocationext.bin` 未同步。
本次按现有 CI 流程从当前源码重新链接、strip、加密并更新该预置资产；没有修改地图或新增 Hook。
重建前后 APK 的 Java/DEX 内容相同，内容变化为 Native 载荷及版本控制元数据。

| 项目 | 小米 11 Ultra | Redmi K50 |
| --- | --- | --- |
| 加载、Hook 安装、启用、停止、再次启用 | 通过 | 通过 |
| 独立接收端加速度、陀螺仪和磁场 | 通过 | 通过 |
| 独立接收端 GPS 缓存匹配测试坐标 | 通过 | 通过 |
| 海拔 1234 m / 3200 m 对应气压 | 约 873.53 / 683.44 hPa | 未提供气压传感器 |
| 步数计数器的整数布局 | 重建后为正常小整数 | 静置时未返回计数事件 |
| 停止后真实传感器数据恢复 | 通过 | 通过 |
| 恢复原包并重启后 Native 已卸载、禁用 | 通过 | 通过 |

小米的步行阶段加速度 Z 轴标准差约 1.00 m/s²，停止后回到约 0.004 m/s²；
Redmi 对应约 1.00 / 0.008 m/s²。小米停止后气压回到约 1007.50 hPa。
样本时间戳递增、数值有限，接收端没有注册错误。两机均未覆盖真实步行触发的步进检测事件，
不将未产生的事件计为通过，也不据此宣称其他 ROM 或全部传感器通道兼容。

四种 ABI 的 Native 源码链接检查及更新载荷后的三架构 Release 构建、APK 检查通过。
最终 arm64 / all / x86_64 未签名 APK 分别为 28,934,838 / 33,335,374 / 19,658,412 bytes，
与表中四舍五入后的体积一致。两机已停止模拟、恢复原包并重启卸载 Hook；测试工具及临时文件已清理，
SELinux 保持 Enforcing。正式 CI 已有从当前源码生成载荷的步骤，本地验证也应先重建载荷，避免使用过期预置资产。
