# Compose 界面迁移与地图切页验证

验证日期：2026-11-21。真机为 Redmi K50、Android 14（SDK 34）、HyperOS 2；本次界面验证不代表其他 ROM 或后端能力验证。

## 迁移范围

- 主界面的侧栏、模式切换和工具栏、定位接收诊断页、悬浮摇杆与目标菜单、自有授权和设置对话框统一使用 Compose 和项目主题。
- 环境/卫星和资料库的标签页由 Compose 排版，使用官方 `fragment-compose` 容器保留子页面控制器和状态。Fragment Navigation 继续负责已有目的地、深链和返回栈。
- 删除已替换的 XML 页面、对话框、列表适配器及 View Binding。保留旧页面类名作为进入 Compose 页面的兼容入口，历史地点、路线模型和用户数据不随界面迁移删除。
- 地图 SDK、方向手势和卫星雷达仍通过 `AndroidView` 互操作。导航图、主题、图标等 XML 资源继续保留。
- 首页默认仅显示左侧菜单和右侧搜索按钮；点击搜索后输入框在顶部向左展开，可收起、提交搜索，并在界面重建后恢复输入。

## 地图黑闪的原因与处理

原始 K50 录屏中，新页面工具栏已显示，旧地图控件仍在退出动画内，地图渲染区域却变成黑色。仅将 SDK 暂停延后到页面不可见、或在切页前请求 SDK 截图，均未消除复现。

最终使用腾讯 SDK 的 `TextureView` 模式和高德 `TextureMapView`，使地图参与页面的透明度和移动动画。同时保持根导航容器尺寸稳定，由各页面应用自己的系统栏及工具栏边距，避免工具栏出现时先改变退出中地图的尺寸。地图生命周期调用保持幂等，可见退出期间延后停止，返回时复用，内存压力及 Activity 销毁时释放。

K50 腾讯地图按实际控件位置执行三轮“地图→设置→地图”，录制的 1692 帧中未检出大面积黑帧，并人工检查实际切页画面。原始截图与录屏包含设备位置，仅本地保存。高德已覆盖创建、离屏复用、内存释放和重建，但本轮截图未显示地图瓦片，因此不将其作为高德鉴权、地图内容或黑闪通过的证据。

## 测试实现注意事项

Activity 1.13 的 Compose 返回处理通过 NavigationEvent；定向测试使用 `DirectNavigationEventInput`，在抽屉动画结束后等待 Compose 提交处理器状态。预测返回期间，退出中的页面可进入过渡层，不再出现在活动 Fragment 列表或普通容器子项中；测试直接检查原始页面 View 的挂载状态，取消后等预览清理，再验证下一次完成返回。失败收尾也先取消手势，避免测试退出 Activity 时二次破坏未完成的返回操作。

独立悬浮窗由 WindowManager 异步布局，Compose 空闲不保证其已显示；测试等待实际显示后再操作。关闭后再次显示时使用新的 ComposeView 和生命周期，避免复用旧窗口的重组关联。帧统计通过锁内复制回调样本，避免统计过程中并发修改。能量轨道动画检查单独启用动画比例并在结束后恢复；应用仍遵守系统关闭动画的设置。

UI CI 中的系统对象/Parcel 检查在普通测试应用内调用模块辅助类，需要临时开放非 SDK API 访问并在退出时恢复原策略；这不表示普通应用具备系统模块权限。需要保持模拟十分钟供独立接收端检测的权限 canary 仅显式启用，不属于普通模拟器 UI 测试。
