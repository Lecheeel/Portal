# LocationService v1.7.5

本版本修复定位订阅丢失和停止状态下的误拦截，增加接收端证据及标准定位通道恢复。

## 修复与改进

- Xposed 保留 Android 自己的监听注册和分发流程，不再手动分发后清空监听表。
- 修正 GNSS 批量回调参数索引、AbstractLocationProvider 方法查找及回调参数边界检查；批量改写保留位置条目数。
- 单次定位、Fused、监听注册和普通附加命令在未运行模拟时透传；保留启动前可用的认证控制通道。新配置默认允许单次定位和 Fused，保留已有显式偏好。
- 标准后端在位置提交及 Provider 操作前后核对授权。授权失效明确报错，不自动争抢授权；清理未完成时保留持久化重试记录。
- 新增“重建标准定位通道”，保留当前场景、路线进度和暂停状态，清理失败不继续注册。
- 新增“独立进程接收诊断”：分别观察 GPS/Network/Passive/系统 Fused 及可用 Google FLP 的缓存、单次和持续样本，记录 `isMock`、样本年龄、时间戳及顺序。日志有界；空结果不判定为非模拟；离开页面取消订阅。
- 发布流程要求完整签名 Secrets，校验升级证书、版本、ABI，附带 SHA-256 校验文件与验证报告。

## 安装与验证边界

- 小米等 arm64 手机优先安装 `LocationService-v1.7.5-arm64.apk`；通用包为 `-all.apk`，模拟器可用 `-x86_64.apk`。versionCode 为 `1790000012`。
- 使用现有 GitHub Secrets 在 CI 内签名，公开签名证书必须与 v1.7.4 一致，以支持覆盖升级。
- 标准无 Root 模式仍是系统 Mock Provider，不能承诺隐藏模拟标记。接收诊断与主应用共用包名和 UID，不能代表网友检测 App 的判定。
- 自动化包含 JVM 回归、Python 发布校验、Android lint、模拟器 UI 与系统定位往返测试。小米 Android 17 真机和实际 Xposed/Native 注入仍需设备验收；升级 Xposed 模块后需重启。
