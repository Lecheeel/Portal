# GNSS 真实画像与输出一致性修复

本轮目标是删除固定卫星模拟来源，以真实采集画像或完整广播星历驱动输出；修复设置、数学模型、投递生命周期和验收工具。不能用切回固定 31 颗、凑足在用卫星或伪造有限 DOP 作为完成条件。

## 已落地的基础实现

- 观测帧、设备/系统/时间/位置元数据、星座身份、数量/仰角/CN0 分布和在用比例。
- 原始测量及接收机时钟字段、导航电文原始载荷独立保存。收到电文不等于已有完整可传播星历。
- 卫星页精确位置权限申请、60 秒真实采集、取消、本机原子存储；原始采集不进入 Android 备份。
- 采集器等待后端配置恢复，再核对本地和系统端停止状态；窗口内发生过模拟启停、状态无法确认或收到 mock Location 均废弃采集，所有监听器在 finally 注销。
- 画像有效性检查：帧数、观测跨度、坐标、有效期、地平线。
- 星座比例采用累计该星座卫星样本数除以累计全部卫星样本数。置信区间用 10 秒时间块 bootstrap，短于三个块时返回完整区间，不将相邻帧当成独立伯努利样本。区间仅描述采集窗口，不能外推到其他地区、时段和设备。
- 统计回放使用实测帧的联合分布；正反向回放避免首尾跳变，跨北方向按最短圆弧插值。CN0 来自实测配对值，不使用人为正弦曲线。
- 核心模型支持 0 自动和正数卫星下限；只可从邻近实测帧或具备完整有效证据的广播星历池补充真实身份，容量不足时记录诊断。已接入生产 runtime；App、Schema 和运行时默认值均为 0，保留已保存用户值。
- 几何 DOP 用局部 ENU 视线和各星座独立接收机钟差列，Householder QR 计算协方差。少于所需观测、秩不足或条件数过大时无解；W=I 为等方差几何 DOP，不把 CN0 当作未经标定的伪距方差。
- 带序列号的共享帧缓存，生产路径按接收秒、稳定路由与卫星下限隔离。广播证据源有单调时刻时以单调秒为唯一分帧边界，并隔离开机标识；否则沿用 UTC 秒。UTC 仅作广播帧首个样本的显示时间，不与单调秒交叉分帧。全局、固定点、独立场景分别持有接收机帧，同一路由每秒首个样本锚定状态、NMEA 和 extras；100ms 运动、海拔、速度及物理噪声更新不再反复创建卫星帧。
- 认证配置通道可下发有界压缩状态画像，压缩载荷限长且解压限量；原始测量/导航电文留在本机。

生产 GnssStatus、NMEA 和 GPS Location extras 已切换到接收机帧。旧固定 5 颗/31 颗模型、工厂、状态桥接器、配置枚举、运行时字段及 Schema 选择器已删除；旧偏好不再读取或下发，调试 API 对旧选择器返回明确错误。用户磁盘中已有的旧偏好不主动擦除，旧配置消息中的模型键不参与运行时选择。以上仅经 JVM 检查和 Kotlin 编译，尚不构成真机验收，完整目标仍未完成。

## 独立分布对照

Detector 的 JSON 报告新增 `gnssEvidence`，保存回调到达时间和逐信号卫星字段；非有限数值保留为字符串证据，不能让 JSON 序列化异常掩盖无效观测。报告没有自动证明数据来自真实接收机。先在已确认停止模拟的环境保存参考窗口，再采集模拟窗口；记录设备、位置、时段、接收环境、后端和实际最少卫星数设置。

独立脚本同时接受本机 `receiver-capture.json` 和新版 Detector 报告，不引用 Kotlin 模型或检测实现：

```sh
python scripts/compare_gnss_profiles.py receiver-capture.json detector-after.json --minimum-satellites 0 > comparison.json
```

每个 UTC 秒取最后一帧，避免同秒突发回调获得更大权重；数量、星座占比、在用比例按唯一星座/SVID 计算。在用身份取该卫星任一信号在用，不把多频计成多星。星座比例仍为累计该星座独立卫星样本数除以累计全部独立卫星样本数。报告可见数量与星座经验分布的总变差 `TV = ½ Σ |pᵢ − qᵢ|`，0 表示本次经验分布相同，1 表示互不重叠；还列出新增/缺失身份。逐信号联合直方图使用星座、5° 仰角箱和 5 dB-Hz CN0 箱，90° 纳入末个仰角箱。两边都保留原始逐信号证据时才报告该距离；频点覆盖变化也会改变该分布，不能单独据此判定模型失真。

均值和比例差采用两个窗口分别重采样的非重叠时间块 bootstrap，固定种子 0、1000 次，给出边际 2.5%–97.5% 百分位区间；默认块长 10 秒，可用 `--block-seconds` 改为其他长度检查敏感性。该方法假设窗口近似平稳、块间依赖较弱，默认块长不保证适合所有接收环境。共享同一画像的回放也不形成新的独立真实观测。每边不足 20 个接收秒、30 秒跨度、3 个块或完全没有卫星时不提供区间；采样空隙单独提示。

结果为描述性对照 `DESCRIPTIVE_ONLY`，不是来源真伪判定、统计等效性检验或自动验收 PASS。区间只描述这些窗口；包含零不能证明等效，多条边际区间也没有同时覆盖保证。正数卫星下限会主动改变分布，必须与自动模式分别评价。当前测试使用可解析的已知比例/计数/差异样本，尚无该设备的有效真实卫星窗口可据此完成分布验收。

Detector 应用内也已接通参考窗口比较。先关闭所有模拟、运行实测检查，再明确选择“将本次 GNSS 窗口设为参考”，填写地点和遮挡情况。保存会替换旧参考，下次检查生效；也可清除。原始状态窗口、设备系统指纹、保存时间和环境备注原子保存在本机非备份目录；不自动选择参考，不把用户标记当作真实来源证明。至少 20 个接收秒、跨度 30 秒、相邻保留帧间隔不超过 2 秒且存在可见卫星才可保存。设备或系统指纹改变、文件损坏和版本不支持会明确跳过比较。

C06 与导出报告展示参考/当前平均可见数、在用比例、星座比例，以及数量、星座和逐信号星座/仰角/CN0 联合分布总变差。计数与分箱定义与上述独立脚本一致；应用内只提供描述性值，不计算 bootstrap 区间、不设真伪阈值，字段检查 PASS 不代表画像等效或定位真实。窗口时间倒退和无效字段不能通过过滤后继续比较；短窗口和采样空隙明确提示覆盖不足。独立脚本仍用于时间块区间和块长敏感性检查。

GPS 广播信号校准改为优先使用原始逐信号状态，避免 spacecraft 投影选中在用 L5 后丢失实测 L1。插值仍只在本次 GPS L1/未知载频的实测仰角范围内进行；跨进程传递严格有序、有限值的紧凑校准结点，反复编码保持相同插值，原始逐信号记录仍留在本机。新的原始记录优先于旧紧凑校准；旧的仅投影画像继续从原有字段重建，不添加空占位校准。

真机还发现并修复两个检测器问题：C05 先检查 `has*` 再延迟读取可选 Location 字段，避免 Android 14 未提供 MSL 高度时 getter 抛异常；C07 将 quality=0 且卫星数字段显式空白的 GGA 保留为缺失证据，不补零、不误报非法，带定位解的缺失数或非数字仍拒绝。Detector JVM 全套与开发包构建通过；独立应用前台短时复测 C05=PASS、C07=UNKNOWN，后者仍缺 GSV 和有效数量对账，不能宣称跨来源验收通过。

为隔离 Hook，临时停用 Portal 模块并重启，Vector 确认启用模块数为 0；独立 Detector 前台采集 120 秒得到 119 帧，其中 117 帧非空、最多 49 颗，全部 5,355 条记录 CN0=0、usedInFix=false，无 GPS 定位解。系统 GNSS 引擎已启动，Qualcomm GNSS HAL 进程存在。零信号/无解在无 Portal Hook 时仍复现，尚不能确定环境、系统或硬件的具体原因。对照结束后恢复原模块配置并重启，临时 USB 常亮设置恢复原值。

### 采集隔离与画像保护

本地场景控制器保留启动代次，系统运行时原子保留模拟 enabled 的变化代次及进程实例 ID。认证状态一次读取这三个系统字段，避免将不同时刻的值组合成停止证据。采集开始、期间和结束分别核对；一次完整启停即使落在两次轮询之间也会废弃整个窗口。系统实例变化或认证状态丢失同样拒绝，不在采集中重新连接来掩盖证据中断。结束时先冻结回调缓冲，再核对最终状态。

Hook 后端必须能确认系统模拟停止，缺少新状态字段的旧模块需要更新并重载。标准 Mock Provider 可以在没有 Hook authority 时采集，但已观察到的系统模拟不能忽略，中途出现/丢失 authority 也不接受该窗口。Native 在当前架构中扩展传感器，定位仍由 Xposed 提供；不把 native_enabled 单独当作 GNSS 模拟开启证据。

生产画像写入新增回放条件检查。缺少真实坐标、有效观测不足或过期的采集不能替换原画像；完整原始记录保存在不参与生产下发的本机 `gnss/latest-rejected-capture.json`，只保留最近一次失败窗口并排除 Android 备份。界面报告具体拒绝原因，不再提示画像保存成功；读取原画像不因本次失败而改变。存储回归核对拒绝前后生产文件逐字节一致，并确认诊断记录可独立读取。

M2102K1C / Android 14 重启加载新模块后，两项真机回归通过：界面空闲但系统已模拟时，采集在注册前拒绝；采集中发布并立即停止系统模拟，变化代次增加两次，窗口被拒绝，随后新采集能收到回调。测试使用控制器自身 UID，未写生产画像或修改用户后端设置。

另一次对照临时停用全部模块并重启，确认系统认证接口不存在后，使用实际 AndroidMockProviderPort/MockProviderBackend 测试必需 GPS/network 通道。两轮启动、连续提交、停止及再启动通过，GPS 回调和缓存保留系统 mock 标记，回调未添加 satellites/meanCn0/maxCn0 字段，停止后持久 Provider 所有权清空。可选 fused 设置未改动，模拟位置 AppOp 恢复原值。该对照覆盖这台 Root 测试手机的标准 API 路径，不是另一台无 Root 设备、独立第三方接收者或有效 GNSS 画像验收。

恢复模块后，新增无画像透传真机回归通过。测试先认证读取完整系统快照，确认 gnssSource 不存在，再启动模拟样本并保持租约；期间接收到真实 GNSS 状态，新旧原始测量监听均可注册。重复注册同一个状态回调后，Android 当前 Status Provider 中该包只有一条登记；两个测量监听为两条登记。运行中注销旧测量与状态监听、停止后注销新测量，dumpsys 当前登记数量依次恢复为零，未将历史 Event Log 计入。测试不清除或写入用户画像，不修改 GNSS 策略；它覆盖无画像时的状态/测量路径，未验证有效画像主动注入、NMEA、Binder 在途竞态、死亡恢复或独立应用路由。

### 独立接收进程的移动与死亡回归

新增显式启用的 `GnssIndependentReceiverDeviceTest`，先确认 Portal 与 Detector 属于不同 UID，并保留原后端与用户设置。测试仅在系统内存中下发标明为合成的七星座、28 个身份画像，每 100ms 更新向北移动的样本并开启物理噪声；生产画像文件不写入。独立 Detector 前台运行 20 秒，通过公开 Android 回调采样，不引用 Portal 的模型或 NMEA 实现。

真机验证发现 C05 原来只检查最新位置，最新 fused 回调可能掩盖较早 GPS extras 的差异。现改为检查整个位置窗口，并分别报告带 GNSS extras 的 GPS 数量、实际完成同时间窗对账的数量和不同坐标数；可选字段仍按 `has*` 延迟读取。JVM 回归覆盖后到 fused 掩盖、较早非法字段、陈旧状态不能配对以及高频移动样本共享同一状态帧。

C07 也改为逐组核对全部完整 GSV 与同时间窗状态帧，比较可见身份集合，不再只检查最后一组数量。两个新增用例在修复前分别复现“后续一致历元掩盖早期数量差”和“数量相同但早期未在用身份不同”的漏报，修复后通过；多频记录仍按唯一身份对账，未报告的星座不混入比较，GN 编号歧义不猜测。同时间窗差异保持 UNKNOWN，并报告实际配对组数、身份差异组数与最大数量差，不据此判定来源造假。

两个真机用例通过。普通运行和接收进程重启后的报告均为 C05/C06/C07 PASS；重启后的 480 个位置样本中，160 个 GPS 样本都具有不同坐标且全部对账，19 帧状态和 304 句 NMEA 的卫星数量、在用身份与 talker 一致。测试要求 20 秒内至少 100 个 GPS extras 样本、每个都实际配对，并限制状态帧数，避免仅凭最新 fused 字段或重复投递通过。

死亡用例在 Detector 正在采样且系统 Status Provider 中有一条登记时强制结束该进程，确认 PID 消失、该包登记归零，再启动新 PID 并重新采样；结束后登记再次归零。只统计当前 Provider 区段，不计历史 Event Log。此项验证接收进程死亡和重新注册，不证明精确命中了在途 Binder 回调竞态，也未直接观测 Hook 内部 NMEA 注册表或热重载恢复。结束时清空临时系统画像、停止模拟并核对 NMEA/噪声/最少卫星数/GNSS 设置恢复；未新增正式 APK 交付。

### 普通 Location 监听生命周期修复

真机新增回归先保持模拟停止，连续 20 次向 GPS 注册同一个公开 `LocationListener`。修复前模块订阅数从 19 增至 39，应只新增一条；`hookILocationListener` 也会重复安装相同回调 Hook。原死亡通知仅在带 Binder 参数的重载里清理，零参数实现为空，显式注销没有保存并解除死亡通知。

新增按 Binder 管理的 `LocationCallbackRegistry`，同一 transport 只链接一个死亡通知，同一 Provider 去重，同时保留 GPS/network 等不同 Provider 的订阅。显式注销或死亡移除全部订阅与路由，并解除通知；死亡回调使用兼容旧 API 的零参数接口。增加注册时死亡、迟到旧通知、未送达死亡通知的存活检查、路由失败回滚及清空的 JVM 回归。普通回调 Hook 改为按实际 Method 去重安装，批量/flush 路径删除多余的重复安装。

另一项真机回归使用不存在的 Provider，Android 抛出 `IllegalArgumentException` 后，旧实现仍将模块订阅数从 10 增至 11；客户端没有保存成功登记，随后公开注销也不能清掉这条错误订阅。现将走系统 API 的监听/批量登记放在原调用成功后，返回 false 或抛出异常时不入表；系统注销失败也不提前移除模块登记。保留既有显式拦截注册设置，未将该测试结果推广到其绕开原调用的路径。

M2102K1C / Android 14 重启加载修复后，两项设备回归通过：20 次 GPS 登记只增加一个订阅，随后同一 listener 的五次 network 登记只再增加一个，注销恢复基线；不存在的 Provider 仍由 Android 拒绝，模块数量保持基线。七项注册表 JVM 回归、Xposed JVM 全套、App Kotlin 编译及开发包/仪器测试包构建通过。零参数死亡兼容、通知解除和注册中死亡的详细断言来自 JVM Binder 替身，尚无 Android 12 设备对照；厂商批量定位也未实际调用。更新本机开发包前核对相同调试证书，未卸载应用、改动生产画像或发布正式安装包。

随后在相同模块版本上完成五项 GNSS 设备回归：独立接收进程移动/死亡重启、全局/固定点及动态下限输出、无画像透传全部通过。独立接收报告包含 170 个 GPS extras 样本，全部完成同时间窗对账；20 组 GSV 身份和数量差异均为零。临时源和策略由各用例恢复，真实画像及多系统广播验收仍未完成。

## GPS 星历实现与后续验收

GPS LNAV 的纯 Kotlin 数学、本机采集解码及 GPS 分量生产输出已接通。位序/字校验按 Table 20-XIV，组帧要求同一卫星、同一个 30 秒发送帧和完整 IOD；扩展拟合期按 Table 20-XII，保留区间拒绝。完整周号由明确可信的 GPS 时刻解析，不硬编码 GPS−UTC 秒数；接收机时间采用整数/十进制先减偏差再转秒，避免绝对纳秒转 Double 丢精度。

采集保存 Android `BOOT_COUNT`，接收机 GPS 时钟与事件单调时刻形成锚点。至少两个有效锚点跨度 30 秒，已知 GPS/单调时刻各自不确定度不大于 1ms，所有锚点相对末锚点的 GPS 时间差与单调时间差残差不大于 1ms，且整个采集没有硬件时钟重置，才允许关联。事件与回调到达时间还须顺序正确、相隔不超过 10 秒。目标模拟时刻为 `GPS_anchor + (elapsed_target − elapsed_anchor)/10⁹`；只接受本机同次开机、目标不早于锚点且外推不超过 1800 秒。这些是模拟证据筛选策略，不是受控 GPS 实时时钟或未来振荡器误差保证；锚点 sigma 不能冒充未来误差上界。

`GnssCaptureWire` 在移除原始测量/电文前建立紧凑广播证据，只纳入真实观测过的 GPS 身份，按规范 PRN 字段容量限制且身份唯一。电文 CEI 结束标签与时钟锚点必须同时代；新原始输入始终重新验证，不能以旧紧凑数据掩盖缺页或失效。已紧凑化的认证配置再次同步时保留证据，继续受压缩、解压及 Binder 预算限制；旧画像没有新字段时仍可统计回放。开机标识读取失败或不匹配、单调时间缺失/过期时明确标记统计来源，不猜 UTC 或完整 GPS 周号。

`ReceiverBroadcastSkyModel` 用目标观察点和同次开机时刻执行 GPS 真空光程/地转/ENU。已知广播身份在地平线下、绝对拟合期外、电文证据年龄超过模拟新鲜度窗口或缺少信号校准时剔除，不能从统计池把同身份补回来；天顶方位未定义时由当前状态适配器明确排除。其余身份保留统计回放，来源为 `HYBRID_BROADCAST_REPLAY`；GPS 可见性改变会改变星座比例，不声称保持原地点比例。卫星下限从有效广播池和邻近实测池满足，最后统一 QR 解 DOP，无解时清除全部在用标志。

GPS CN0 和候选在用频率按本次状态采集中 GPS 仰角的条件经验均值做分段线性插值，已知非 L1 载波不参与。未知载波保持未知；超出观测仰角范围不外推 CN0。候选在用频率达到一半且 CN0 大于零才参与模拟几何，最终是否保留在用标志取决于整体解算；它不是预测实时锁定、目标地点遮挡或未来健康状态。当前生产不生成原始伪距/载波。

新增时钟/紧凑证据/重编码/经验信号/组合几何测试，以及 `CapturedGnssSource` 与 Hook 的贯通测试，覆盖原观察点下无解但组合后可解、目标地点地平线剔除、过期/缺校准不补回、跨开机/冻结 UTC 不复用物理帧、错开时钟边界仅发布一帧、预览来源一致。模型数值仍以既有独立 C 向量验证；新增电文字及 Hook 圆轨道均为明确的合成测试输入，不是真实设备电文。本阶段 Core/NMEA/Xposed/App arm64 JVM 全套、App arm64 Kotlin 编译与模块检查通过，后续缓存/预览改动也通过对应回归；本阶段未安装、启动或采集设备，完整目标保持未完成。

原始采集新增时钟不确定度、漂移、闰秒证据、接收机事件单调时刻与回调到达时刻，兼容缺少这些字段的旧画像。GPS 捕获解码要求已知时间不确定度、附近一致且未重置的接收机时钟；回调到达时刻只用于周号/HOW 关联，不冒充精确发送时刻。缺证据、告警、陈旧、冲突或分页不完整时返回诊断，不由 hasEphemeris 标志推断星历。

GPS 组帧容量满时拒绝新候选，保留已有冲突记录直到采集显式结束/清空，防止缓存淘汰后重放消除冲突。每颗卫星只返回最新发送帧的完整结果；较新帧不完整、冲突或健康状态不可用时不回退旧健康结果。跨时钟重置或某卫星的新电文无法关联单调时钟时，采集解码撤回相关结果；包括重置发生在两个邻近关联窗口之间的情况。新增回归使用独立逐字奇偶重编码构造较新 HOW/不健康消息与冲突，并覆盖容量拒绝后的重放。

广播参数是为 ECEF 拟合的参数，不可将中间轨道坐标当成普通 ECI 再额外旋转。应包含 Δn、六个二次谐波项、IDOT、Ωdot 和 toe 地球自转项；GPS LNAV 的 μ=3.986005×10¹⁴，与通用二体试验常量不相同。计算发射时刻位置，并处理信号传播期间地球自转；钟差多项式、相对论项和 TGD 单独按对应观测信号处理。周跨越修正不能让陈旧一周的星历重新有效，须先以完整绝对时刻检查有效期。

GPS 接收几何通过有界真空光程方程求发射时刻，再将发射 ECEF 坐标旋转到接收时刻的 ECEF 轴。拟合期检查针对实际发射时刻；接收时刻稍晚于拟合期末但发射仍有效的情况可以成立。该模型不含电离层、对流层、天线和接收机偏差，不能据此生成伪距或载波相位。ENU 仰角采用与 asin(up/range) 等价且数值稳定的 atan2；天顶/天底方位角明确未定义，不制造数值。

Galileo、北斗 MEO/IGSO/GEO、GLONASS 必须分别核对接口规范和系统时标；不以 GPS 代码通过代替其他系统验证。每个解码器、每个传播器分别提交，使用独立权威导航向量和可追溯数值结果，补单元/时间/地平线/过期/分页切换等边界测试后才接生产路径。

## 原始测量与真实观察点的证据完整性

状态采集现保存回调到达的 Android 单调时刻，并单独保存其观察点 `Location` 的单调时刻、可用的时刻不确定度、水平和垂直精度。坐标仍只取最近 10 秒内的真实定位，但该筛选策略不等于两者同时观测；保存两种时刻后才能评价测量与坐标的时间差。Android 报告的精度/不确定度不是确定性误差上界。观察点时刻晚于状态回调、无坐标却带时刻、非有限或负精度等矛盾输入拒绝入库；旧画像缺字段时保持未知。本机存储与有界状态载荷往返均保留这些字段。

采集器在接收 `Location` 时检查坐标、正的非未来单调时刻及已声明的高度/精度/时刻不确定度，拒绝异常定位并留下诊断，避免其在后续 `GnssObservationFrame` 构造时中断有效卫星状态采集。每个状态回调只读取一次墙钟和单调到达时刻；保存的观察点 epoch 来自原 `Location`，不拿回调到达时间替代。该 Android 回调路径已编译，尚未执行异常 Provider 真机注入验证。

原始测量同时保留 Android 的 full ISB、satellite ISB、各自 sigma，以及接收机 ISB 参考星座原始编号、载频和码型。每个 `has*` 标志独立处理，未提供时存 null，不默认 GPS/L1/C/A 或零偏差；未知参考星座编号不被改成其他系统。码型也按 `hasCodeType()` 保存。根据本机 SDK 37 `GnssMeasurement.java`，full ISB 可能包含接收机、系统时标、频率/码型及群延迟，satellite ISB 是其中的空间分量，不能把它直接当作 GGTO，也不能把 full 与 satellite 再相加。这里只保留证据，不修改接收到的时间或生成伪距；这些原始字段继续不进入 Binder 状态载荷。

复核 Galileo OS SIS ICD 2.2 §5.1.8 和 SDD 1.3 §3.5.1 后，未获得可直接套用的 GGTO 统一有效时长。±31 周只约束广播时的截断周解析，4 小时是星历年龄限制，不能代替 GGTO 适用期；SDD 的 GGTO 精度/可用率指标也不能当作单条参数的确定性误差上界。SDD 明确允许通过额外观测状态自主估计系统间偏差，但这需要完整测量模型、坐标/时刻和信号偏差处理，当前尚未实现；新增采集证据不等于该解算或 Galileo 生产天空已完成。现有 GGTO 适用期校验保持严格。

共享广播帧另修复 UTC 标签取整：物理几何使用首个样本的精确单调时刻，输出 UTC 时间也保留该样本的毫秒；缓存仍按单调秒统一发布，随后样本复用同一 epoch，不能单独刷新时间而保留旧卫星位置。后续真机回归发现统计路径也须保留首个样本的毫秒：若向下取整到采集结束之前，会使刚完成的有效画像在该秒返回空帧并缺失 Location extras。现所有来源均保留首个样本 epoch，整秒仅作缓存键；早于采集结束的迟到样本直接拒绝且不缓存，避免污染同秒后续有效样本。两项新增 JVM 用例在修复前失败、修复后通过。

上述边界修复后，Core/NMEA/Xposed/App arm64 JVM 全套、App Kotlin 编译和开发包/仪器测试包构建通过；更新模块并重启后，真实 Android 回调上的共享帧集成测试通过。测试使用明确合成的 GPS/北斗/Galileo/GLONASS 四系统、16 个身份，只验证传输与适配：GnssStatus 身份/CN0/在用标志、每 epoch 单次 GGA、四系统 GSA/GSV、几何 DOP 和 GPS extras 的在用数/CN0 一致，最早 Location 回调也须有 extras；下限 128 时仍只输出有效池的 16 个身份。合成画像仅临时下发系统内存，finally 清除并核对恢复，不写用户生产画像。该结果不是实测卫星比例、完整广播星历、动态数量分布或独立接收者验收。

后续将同一集成用例扩展为七星座、28 个合成身份，加入 QZSS 的 Android 193–196 到 GQ 1–4、NavIC 到 GI、SBAS 的 Android 120–123 到 GP 33–36 映射。GPS/SBAS 共用 GP，GSV 分为两页并核对总数，GSA 使用 system ID 1–6；真实 Android GnssStatus、NMEA 和 extras 一致性检查通过。另用临时 PER_APP 规则把控制器包路由到与全局不同的固定点，Location 和 GGA 均报告该固定点，卫星/CN0/DOP 仍一致；结束后核对路由恢复。两个用例通过，但仍是自身 UID 与合成画像测试，不证明独立第三方的路由或真实分布。

有效合成画像下的 raw 注册回归又发现一个框架层缺陷：void 注册接口通过抛出 UnsupportedOperationException 拒绝，但两组 Hook 安装默认使用 PROTECTIVE，libxposed 会吞掉 Hook 主动抛出的异常并继续原始注册。分别修复 GnssManagerService 与 LocationManagerService 入口，将这组原始测量/导航/天线注册和注销 Hook 明确设为 PASSTHROUGH，保留有意的 API 异常及原系统异常；移除仍必达 Android。相关 JVM 回归、Xposed 全套和 App 编译通过。更新模块并重启后，全局与固定点两项 ART 集成回归通过：关闭真实 raw 许可且已有有效帧时，新测量注册明确失败且系统不新增条目；启用模拟前的已有测量监听仍可在运行中注销，登记归零。该结果只覆盖该机的测量入口，不宣称导航/天线的真实载荷、运行中状态通知或所有厂商签名均验收。

最少卫星数也补充实际系统回调验证：临时合成画像的当前帧为 14 个身份，邻近有效池为 28 个。仅固定测试发布样本的 UTC 标签以重复访问同一统计帧，持续更新真实单调租约，不改设备系统时间；依次下发下限 0、20、128、0，GnssStatus 连续两帧分别返回 14、20、28、14 个身份，且全部来自有效池。全局和固定点两个用例均通过，说明下限可生效、容量不足不补造、回到自动后不残留强制数量；这仍不是实测画像的数量分布或设置页端到端验收。

## Galileo 星历基础与缺口

按 OS SIS ICD 2.2 实现独立完整 GST、GTRF 广播传播和双频参考钟差，I/NAV E1/E5b 与 F/NAV E1/E5a 参考显式区分。模型不把 GPS 与 GST 直接互换。解码器按 Galileo OS SDD 1.3 第 17 页与 Annex C.4.4.1 脚注 22，从解析后的完整 toe 建立 `0 ≤ t−toe ≤ 14400s` 年龄上限，附加独立限制只能缩短；这不是以 toe 为中心的 ±2 小时，也不证明服务状态未来四小时持续有效。BGD 和逐信号 SHS/DVS 独立保留，不能将数学轨道可计算等同于信号可用。

单频钟差已按 Tables 71/73 与 Eqs 18/19 接入独立计算器：I/NAV E1 减去 BGD(E1,E5b)，E5b 减去 `(1575.420/1207.140)² × BGD(E1,E5b)`；F/NAV E5a 减去 `(1575.420/1176.450)² × BGD(E1,E5a)`。不拿另一参考的 BGD 直接修正当前钟差，不从缺少该服务状态证据的消息推断可用信号。输入还需通过目标信号 SHS/DVS、SISA、BGD 字段范围和绝对有效期检查；双频参考钟差不额外减 BGD。测试以已有独立 C 钟差向量为基准，使用 Decimal128 和精确频率平方比 `5929/3481`、`23716/13225` 独立核对，不代表已有真机码伪距验证。

GPS 与 GST 之间已实现广播 GGTO 双向转换。GPS 周 1024 和 GST 周 0 的名义纪元对应不等于两种时标偏移为零。按 Eq. 24，`GST − GPS = A0G + A1G × (GST − t0G)`，正向必须求解隐式方程；相对名义 GPS 时刻的修正为 `(A0G + A1G × (GPS_aligned − t0G)) / (1 − A1G)`。反向在 GST 上直接计算多项式。系数保留有符号原始单位，比例分别为 2⁻³⁵ 和 2⁻⁵¹，不夹带 UTC 闰秒、接收机偏差或卫星钟差。两向结果按外部 GST 有效区间检查，不把 ±31 周的截断周解析规则当作有效期。

I/NAV word 10 与 F/NAV page 4 的 GGTO 解码器已落地。使用独立 GPS 证据解析 6 位 WN0G 对应的完整周号，避免先要求完整 GST 再转换 GPS 的循环依赖；仅在四个参数同时为全一时认定 GGTO 不可用，不因单个字段为全一而拒绝。调用方必须给出包含广播时间标签的 GPS 窗口，并计入发送端时钟不确定度，不能直接拿回调到达时刻代替。窗口最多 120 秒是关联策略，不是设备延迟保证；目前尚未建立 Android 采集证据到该窗口的适配。F/NAV 自带 TOW 必须落在窗口内，I/NAV word 10 不带时间戳，输出明确留空；解出的标签也不等于精确物理发射时刻。

转换使用 Decimal128 绝对时间仿射方程独立对照，覆盖正负系数、隐式分母、截断周边界、系统纪元边界与溢出。GPS/GST 时间加减和 GGTO 共用周内秒归一化，修复周边界负微小偏移舍入成 604800 导致异常，以及负次正规数除法下溢的问题；早于系统纪元的输入仍拒绝。合成 GGTO 页的位字段与 CRC 经固定版本 RTKLIB `getbits/getbitu/rtk_crc24q` C 函数核对，这只是字段提取和 CRC 对照，不是额外的独立 GGTO 周号解析器或时间转换实现。没有真实 GGTO 电文、发送窗口及有效期证据，不能据此宣称捕获时钟关联或物理天空输出完成。

Android I/NAV 采用 228 位偶/奇页组合，CRC 覆盖前 196 位，末尾 SSP 不在覆盖范围内；F/NAV 采用 214 位信息和 24 位 CRC。解码前核对载荷长度、填充位、页类型和 CRC24Q。I/NAV words 1–4 要求身份和 IOD 一致，word 5 独立提供 GST 与服务状态；F/NAV pages 1–4 核对共同 IOD、身份及相邻发送时刻。两者解析完整周号并拒绝 SISA 保留值与 NAPA。当前样本为真实 RINEX 参数独立重建的合成页，不是真机原始页。

采集窗口内的 I/NAV 与 F/NAV 组帧器已分别落地。调用方必须为每条输入提供可信的完整 GST，并明确给出采集窗口；完整解码后按 toe 应用 SDD 年龄上限，可额外提供更短的有效区间。最多 120 秒是组帧策略，不是星历拟合期，也不会由 UTC、GPS 周号或 hasEphemeris 推断。两者按卫星和 IOD 隔离，支持乱序；同一 IOD 的轨道/钟差/SISA 冲突会撤回结果，收齐后还须调用 completed() 复核晚到证据。每个组帧器最多保留 64 个候选，F/NAV 另限制 512 个不同发送页，不通过淘汰冲突来恢复输出。新的采集窗口使用新实例，不能拿一个实例持续跨窗口拼接。

按 ICD 5.1.9.2 区分 IOD 数据和独立更新的数据：I/NAV word 5 的 GST、BGD、逐信号健康/DVS 按卫星保存，最新 CED 批次不完整时不回退旧批次；F/NAV 使用最新发送的 page 1 服务证据，同样不回退到旧健康状态。BGD、健康、电离层或时标转换的正常更新不当作轨道冲突；相同发送时刻的服务内容冲突则拒绝输出。I/NAV 不带 GST 的 words 1–4 依赖调用方给出的可信采集时序选择批次，时序相同但 IOD 不同则报告歧义，不靠到达顺序决定。当前只在合成页上验证了这些规则，没有真机原始电文验收。

传播用四条同一 E24 卫星的真实记录，在两个钟差参考下对照 12 组固定 RTKLIB C 结果；覆盖范围不代表其他 Galileo 卫星已验收。CRC 用独立多项式长除法生成并经 RTKLIB C 校验；I/NAV 全参数另与 RTKLIB 解码器对照，F/NAV 参数按源 RINEX 和标准广播量化间隔核对，尚无独立 C 参数解码器对照。组帧测试覆盖全部收页排列、逐页冲突撤回、跨周/4096 周截断、健康/BGD 更新、容量上限和批次切换，组帧结果与完整页解码器对照；这些测试不构成额外的独立参数解码验证。OSNMA 认证、GGTO 真实采集/发送窗口及适用时段关联、真实坐标框架转换、生产天空输出与设备验收仍待完成。

### Galileo 接收几何与采集适配

接收几何显式接受 GTRF ECEF 接收机位置、局部椭球法线方向和接收 GST；不把 WGS 84 输入隐式改名为 GTRF。用轨道最大半径和接收机半径建立光程上界，在绝对有效区间内二分求解 `τ = range(tR−τ)/c`，然后将发射坐标按 `Rz(−Ωeτ)` 转入接收轴。单频入口在解出的发射时刻应用对应 SHS/DVS、SISA 和 BGD；不借此制造伪距、载波、CN0 或在用状态。

新增 12 组独立 RTKLIB C 接收向量，仍为同一 E24 的四条记录，涵盖三个显式合成接收原点/局部方向与多个时刻。C 用固定点迭代，Kotlin 用有界二分，比较光程、接收 ECEF、ENU、仰角、方位和双频参考钟差；单频再按精确频率平方比核对。`scripts/generate_galileo_reception_reference.py` 可从指定固定版本 RTKLIB 源码重建向量；这些输入不提供真实 GTRF/WGS 84 转换证据，微米级数值一致性也不代表广播轨道精度。

GPS 与 Galileo 采集共用已知不确定度和单调时钟关联，邻近距离按整数纳秒判断，避免长开机时间的 Double 舍入越过边界；纪元下溢返回诊断。`GalileoCaptureEphemerisDecoder` 要求独立建立且在适用时段内的 GGTO，随后从采集时钟得到近似完整 GST，供两个组帧器使用。缺少 GGTO 不走零偏移回退；跨时钟重置、超出 120 秒窗口拒绝拼接。某卫星/格式出现无法关联的新电文时撤回该格式的旧输出，不能恢复旧健康状态。当前只是带外部 GGTO 输入的本机解码能力，尚未从真实采集建立 GGTO 来源/适用时段，也未接生产天空。

本阶段 Core/NMEA/Xposed JVM 全套、App arm64 Kotlin 编译和模块规范检查通过。没有新安装、启动、重载或真机采集；生产仍为统计回放，完整目标未完成。

## 北斗传播基础与缺口

按 B1I 3.0 §§3.2/3.3、5.2.4.9/12 与 Table 5-11 实现独立 BDT、BDCS 轨道与无 TGD 的卫星钟差。MEO/IGSO 直接使用 BDCS 升交点公式；GEO 使用规范定义的中间惯性坐标、`Rx(−5°)` 和 `Rz(Ωe×tk)`。这里的矩阵符号按 ICD 的被动旋转约定，不能借用常见主动旋转公式而不换符号。使用北斗自己的地球自转常量 `7.2921150×10⁻⁵ rad/s` 和引力常量，轨道类型显式输入，不按历史 PRN 范围推断；因此支持输入现代 GEO 身份而不错误进入 MEO 分支。

12 组固定 RTKLIB C 数值来自明确标注的合成 B1I 参数，另有圆轨道 GEO 倾转解析检查、跨周连续性、陈旧整周拒绝和数值溢出回归。旧 RTKLIB 参考代码按 PRN 分支，生成脚本仅为选择参考方程映射 GEO→PRN1、IGSO/MEO→PRN6，Kotlin 测试仍保留实际输入的 SVID（包括 59）。这不验证 RTKLIB 的现代卫星分类，也不构成真实北斗电文或轨道精度验证。合成输入仅在测试资源，未加入生产卫星池。D1 解码的原始位读取显式跳过每个 30 bit 字的 BCH 校验位，所有跨字参数按 ICD 分段拼接；toc 与 toe 保持独立，SOW 连续性允许周界回绕，外部有效区间不能由解码器臆造。有效期仍要求独立证据，不把每小时更新/AODE 当作固定拟合期；真实 BDCS 接收机坐标、BDT 与其他时标转换、轨道/服务适用时段来源、真实输入对照及生产天空尚待完成。

### 北斗 D1/D2 解码与组帧

Android D1/D2 的十个 30 bit 字按 BCH(15,11,1) 验证并解交织后，按 ICD 图示位序读字段；传输位序与图示位序不能混用。D1 接收完整子帧 1/2/3，D2/GEO 接收子帧 1 的 pages 1、3–10，page 2 仅含独立电离层信息。D2 钟漂、谐波、偏心率、倾角、升交点速率和近地点幅角包含跨页字段，必须先拼完整位串再处理符号。两个解码器使用 Table 5-11 的半周角转换常量，保持 toc/toe 独立；外部完整 BDT 解析 13 位周号，分别解析周内秒的最近完整纪元，恰好半周歧义、非法秒数和纪元下溢拒绝。

D1 和 D2 分别新增两组独立 RTKLIB C 全参数向量，字段为明确标注的合成输入；正负值及跨字/跨页低位均非零。Python 构造 ICD 逻辑字段及 BCH/交织传输载荷，C `decode_bds_d1`/`decode_bds_d2` 提供参数参考，Kotlin 从 Android 载荷开始对照。参考 C 强制 toc==toe，本机解码器依 ICD 的独立钟参数定义另外测试两者不同；跨周解析也单独验证，不能以旧 C 实现的限制作为标准。生成脚本和 JSON 均只用于测试，不作为生产星表或真实原始电文证据。

两个有界组帧器按卫星与完整发送周期隔离，分别要求可信逐条 BDT、最多 120 秒的采集窗口和独立星历有效区间；120 秒是组帧策略，不是拟合期。D1 的 MEO/IGSO 类型必须由外部提供，D2 使用规范明确的 GEO 类型，均不按 SVID 历史范围猜测。AODC/AODE 保存为年龄证据，不当作 issue ID 或拟合时长。候选最多 64 个，容量满拒绝新候选而不淘汰冲突；较新不完整周期、晚到 BCH 合法冲突、容量拒绝均不能回退旧结果，重放不能恢复冲突候选。调用方须在采集结束后以 `completed()` 重新核对，不能保留此前返回值当作最终结果。

### 北斗接收几何与单频钟差

`BeiDouReceptionGeometry` 使用显式 BDCS ECEF 原点和局部椭球法线方向，接收/发射时刻均为完整 BDT，不把 WGS 84 或 GPS 时间隐式改名。由最大轨道半径与接收机半径建立真空光程上界，在绝对有效区间内二分求解发射时刻；用北斗的地球自转常量将发射坐标按 `Rz(−Ωeτ)` 转入接收轴，再计算 ENU。新增 12 组独立固定点 C 向量覆盖合成 GEO（含 SVID 59）、IGSO、MEO，比较光程、接收 ECEF、ENU、仰角、方位及钟差；输入仍非真实导航电文、接收机坐标或坐标框架转换证据。

B1I 3.0 §5.2.4.10 的单频修正分别为 `Δtsv(B1I) = Δtsv − TGD1`、`Δtsv(B2I) = Δtsv − TGD2`，不套 Galileo 的频率平方因子。在几何解出的实际发射时刻检查轨道有效期、SatH1、URAI 和目标信号 TGD 范围；URAI=15 表示机动或无精度预测，不能作为可用结果。另要求调用方独立给出服务适用区间，同时覆盖服务广播标签与目标发射时刻；轨道拟合期不自动充当健康状态可外推的依据。这些计算不生成伪距、载波、CN0 或 usedInFix。

本阶段 Core/NMEA/Xposed/App arm64 JVM 全套、App arm64 Kotlin 编译与模块规范检查通过；这些代码尚未连到真实采集的 BDT/轨道类型/有效期来源，也没有生产天空集成。B1I 3.0 §§5.2.4.19–21 的系统间时间参数标注“Not broadcast temporarily”，不能把空字段或零值当作已得到真实 BGTO。真实多系统数据、跨来源设备验收和完整目标仍未完成。

## GLONASS 状态向量传播与缺口

新增 `GlonassBroadcastStateVector` 与 `GlonassBroadcastPropagator`，按 GLONASS FDMA 的位置、速度、日月摄动加速度在旋转 PZ-90 ECEF 中做 RK4 积分，不套用 GPS/北斗的 Kepler 元素。输入显式携带 PZ-90.02 或 PZ-90.11 框架标签；标签来自调用方的导航数据证据，不按槽号推断，也不执行框架转换。分量使用 SI 单位，检查符号幅值字段的可表示范围、有限数值及地球外初始位置。槽号按五位字段校验，未把历史 24 槽或某次实际接收到的数量写成生产星表。

采用 ICD 5.1 A.3.1.2 的简化动力学常量 `μ=3.9860044×10¹⁴ m³/s²`、`ae=6378136 m`、`J₂=1.0826257×10⁻³`、`ω=7.292115×10⁻⁵ rad/s`；不混用 Table 3.2 的椭球重力场常量或 GPS 常量。设 `j=3J₂μae²/(2r⁵)`、`b=5z²/r²`、`g=−μ/r³`，三轴加速度为：

```text
ax = [g − j(1−b) + ω²]x + 2ωvy + ax_luniSolar
ay = [g − j(1−b) + ω²]y − 2ωvx + ay_luniSolar
az = [g − j(3−b)]z + az_luniSolar
```

实际读取的 UNAVCO ICD 镜像和 QCAR 044 原页均印成 Y 方向 `+2ωvx`、Z 方向 `j(1−b)`，不能照抄。修正来自旋转坐标恒等式 `a_rot=a_grav−2Ω×v−Ω×(Ω×r)+a_luniSolar` 和 J₂ 势函数梯度，与固定版本 RTKLIB 明确标注的两处修正一致。测试另外以正引力势 `U=μ/r·[1−J₂(ae/r)²P₂(z/r)]` 的中心差分梯度核对三轴引力，并独立核对科里奥利、离心和日月摄动项，避免只用两份相同错误的代码互相证明。

积分步长最大 10 SI 秒，最后一步取剩余时间，支持正向与反向、非整步时距。当前按 ICD A.3.1.1 的严格 `|t−tb|<900s` 上限执行（QCAR 的对应段落写为 `≤15min`）；边界本身拒绝，不按日/周取模使陈旧数据复活。该上限只限定简化动力学的外推，不证明轨道、健康或服务状态可用。每个中间 RK 阶段检查数值及位置，地球相交轨迹拒绝输出。

`scripts/generate_glonass_reference.py` 已用本机 C 编译器实际重建：输入是固定版本混合 RINEX 中 2013 年的全部 4 条 GLONASS 记录（两个槽、各两个时刻，属于 PZ-90.02），不是生产卫星集合。输入文件与远端固定版本逐字节比对相同，脚本校验 RINEX 与 `ephemeris.c` 的 SHA-256。独立 C `glorbit` 在 60/10/1 秒三组步长上输出 28 个时距的坐标和速度，Kotlin 对照 10 秒结果及 1 秒收敛结果；这些样本的最大坐标分量差分别约为 0.507 毫米（60 对 1）与 0.399 微米（10 对 1）。这是离散积分数值对照，不是广播轨道精度、现代 PZ-90.11 实测验证或当前星座分布证据。

### GLONASS 字符串与即时参数

`GlonassNavigationStrings` 按 Android GLO L1 C/A 的 11 字节大端载荷读取 85 位，跳过高位 B86–B88；不能直接套 RTKLIB 左对齐、末尾补三位的缓冲区。检查长度、填充、idle chip、已知槽号、帧/字符串元数据与编码字符串号；按 ICD Table 4.13 的七组位集合与总奇偶校验逐项验证。即使 HAL 标为 PARITY_PASSED/REBUILT 也重新核对，当前保守拒绝任何非零 syndrome，不自行纠错或猜测位对齐。严格拒绝部分仅校验位损坏的字符串可能损失可用数据，但不会把未验证载荷当成星历。

新增 15 种字符串的独立 C 校验/字段向量，Python 使用固定 C 源码的字节掩码求校验位，Kotlin 则使用 ICD 位编号集合；C `test_glostr/getbitg` 核对干净载荷与符号幅值字段。测试逐一翻转这 15 组载荷的全部 85 个传输位和 3 个填充位（含 HAL passed/rebuilt 两种标签），并对一组载荷穷举全部传输位的双比特破坏。测试载荷为明确合成数据，不是真实 Android 接收样本；不能据此宣布厂商 HAL 打包已验收。

`GlonassImmediateDecoder` 支持 GLONASS-M 的 strings 1–4，解码位置/速度/日月摄动、τn、γn、Δτn、Bn/ln、FT、En、P/P1–P4、tk/tb 和 NT；不把符号幅值当补码，不将年龄/更新间隔当拟合期。原始健康位保留，不把字段可解码等同于信号可用。检查完整无重复字符串、槽/帧一致、编码槽号、GLONASS-M 类型、日序号和时间字段范围、30 秒到达窗口与轨道数值。该到达窗口只是传输健全性检查：相同帧 ID 每个超帧重复，尚不能证明四条字符串属于同一实际发送周期。

另有 4 组独立 C `decode_glostr` 全参数对照，轨道参数从上述真实 RINEX 量化重编码，钟参数、日期、标志与全部字符串明确为合成输入。Kotlin γn 使用精确 `2⁻⁴⁰`；固定 C 源码的十进制 P2_40 宏略有舍入，测试显式区分不超过两个 ULP 的该参考误差与严格的 ICD 二进制缩放，未将舍入误差复制进实现。旧 GLONASS 或其他 M 字段变体目前拒绝，不按 GLONASS-M 解释预留字段。

### GLONASS 连续时钟域、组帧与接收几何

`GlonassCalendarCoordinate` 按完整 N4/NT 解析公历日期，保留日内标签；没有 N4 时不猜最近世纪或将 1461 天取模。`GlonassTimeDomain` 要求外部明确给出连续时钟证据及其覆盖区间 `[from, until)`，相同诊断 ID 不会合并两个独立域。UTC 闰秒修正前后和接收机时钟重置后必须使用不同域，不能简单把相邻民用日标签当作等长 SI 时间。ICD Appendix 2 要求旧星历继续使用旧修正尺度直到接收新星历；本模型提供在单个连续尺度上运算的表达方式，**没有**自动取得这项真实证据或实现 UTC/GPS/UTC(SU) 转换。内部时刻拆为公历日、整数秒和秒内小数，光行时加减不回写成日内大 Double；显示坐标会舍入，不能再拿显示值重建精确计算时刻。测试覆盖跨日/跨年/四年边界、2100 年公历非闰年、域边界、不同域拒绝及皮秒级加减回归。

`GlonassReferenceEpoch` 使用独立完整发送排程日期核对 NT，再将 tb 解析到最近的完整日，恰好半日歧义、非法 tb、缺时钟覆盖均拒绝。`GlonassL1caAssembler` 的窗口最多 120 秒、候选最多 64 个，按完整日期、30 秒排程和槽号隔离；必须逐条提供已建立的名义卫星排程标签，核对 2 秒字符串次序、30 秒 tk 和五帧周期的 frame ID，不能用到达时刻或物理系统时刻冒充卫星 tk。晚到校验合法冲突保留，缺排程或域变化隔离该卫星；较新不完整/损坏周期和容量拒绝均撤回旧输出，重放不能恢复。采集完成后必须重新调用 `completed()`，不能缓存早先返回值当作最终结果。这是有显式输入证据约束的组帧组件，真实 Android 采集到该证据的适配器尚未完成。

`GlonassOrbitalEphemeris` 与 `GlonassAbsolutePropagator` 加入独立绝对轨道适用区间，要求与 tb 同一时钟域且处于严格 900 秒积分上限之内；En、P1、数学上限本身均不自动生成适用区间。区间包含 tb，目标时刻越界、跨域或陈旧一天/一周拒绝，不按日/周回绕。该对象只是轨道适用证据，不包含健康或信号可用承诺。

`GlonassReceptionGeometry` 要求接收机 ECEF 原点和局部椭球法线方向显式处于与轨道相同的 PZ-90 实现，拒绝 PZ-90.02/PZ-90.11 混用，不隐式将 WGS84 改名。以轨道适用区间建立光程方程括区间，最多 60 次二分求解真空光行时；在实际发射时刻检查轨道，将发射 ECEF 坐标以 `Rz(−ωτ)` 转到接收轴一次后计算 ENU。接收晚于适用期末但发射仍有效的情况允许，发射越界不能通过放宽有效期掩盖。新增 12 组独立 C 固定点/一秒积分向量，对照光行时、接收 ECEF、距离、ENU、仰角和方位，另测有效期端点、午夜和框架/时钟域不匹配。轨道输入为上述历史真实 RINEX 参数，接收原点、方向和时钟关联明确为合成测试条件，不是真实坐标转换或时标证据。

仍缺少 Android 真实逐条排程/时钟证据的采集关联、UTC 修正与 UTC(SU) 关联来源、独立轨道适用期来源、健康/钟差/逐信号服务检查和真实框架实测证据。新增的 `GlonassBroadcastEvidence` 已把连续时钟域、PZ-90 框架、显式接收机变换、健康和有效期作为可序列化证据，并接入 `ReceiverBroadcastSkyModel`；缺证据时仍只走统计回放。当前返回的数学几何不生成伪距、载波、CN0 或 usedInFix，不代表目标地点已有可用多系统物理天空。完整目标仍未完成。

### GLONASS 时间、年历健康与钟关系

按 ICD 5.1 §4.5/Tables 4.9/4.11 新增 GLONASS-M string 5 原始参数解析。调用方必须提供独立关联的 M=01 格式证据；完整 N4/NA 建立年历日历标签，拒绝未知年代和 2100 年非闰年造成的非法日号。τc 按符号幅值 32 位、2⁻³¹ 秒解析，τGPS 按 22 位、2⁻³⁰ 秒解析；§4.5 明确后者是 GPS−GLONASS 的秒数小数部分，Table 4.9 的印刷单位“day”不作为乘一天的依据。接收到零系数不证明转换可用；GPS 整数偏移、UTC(SU)−UTC、连续时钟域与适用区间仍需独立证据。

年历健康解码保留广播者与被描述卫星的不同身份，按 §5.3/Table 5.1 保留 Cn=1 正常、Cn=0 不正常的原始极性。偶数字符串 6/8/10/12/14 才读取 nA/MnA/Cn；第五帧的 string 14（超帧 74）实际包含 UT1 B1/B2/KP，明确排除。nA=1..24 是该旧版接口规范的地址字段合法范围，不是生产星表或模拟数量设置；保留原始电文以支持未来消息格式。Cn 本身不是当前服务许可，还需即时 Bn/ln、年历时刻关联与有效性检查。

`GlonassClockRelation` 严格使用 §3.3.3 的 `U = S + τc + τn − γn(S−tb)`，U 为 UTC(SU)+3h，S 为卫星钟读数。给定系统时刻时，解析求解 `S−U = [−τc−τn+γn(U−tb)]/(1−γn)`；不能将系统时刻直接代进卫星钟多项式而省略分母。反向接收已独立解析完整日期的 `S−tb`，不会将卫星钟读数标记成系统时刻或按日回绕。τc 必填，γn 已含广播的引力/相对论频率预测，不再次添加 GPS 轨道偏心率项。时钟适用区间由外部独立提供，跨域、过期、非有限数和超出广播字段范围的系数拒绝；这仍不证明卫星或信号健康。

两套各 5 组明确合成载荷，分别实际经固定 RTKLIB C `test_glostr/getbitu/getbitg` 校验奇偶和原始字段；这是位提取对照，不是独立完整时间/年历解码器，也不是真实接收机电文。时钟关系另以 50 位十进制算术解仿射方程，对照系数正负组合、跨午夜、区间端点、不同域、非法值和双向往返。Core JVM 全套及模块规范检查通过；新组件尚未接入真实逐条排程、服务许可和生产天空，本阶段未更新设备包。
