# GNSS 真实画像与输出一致性修复

本轮目标是删除固定卫星模拟来源，以真实采集画像或完整广播星历驱动输出；修复设置、数学模型、投递生命周期和验收工具。不能用切回固定 31 颗、凑足在用卫星或伪造有限 DOP 作为完成条件。

## 已落地的基础实现

- 观测帧、设备/系统/时间/位置元数据、星座身份、数量/仰角/CN0 分布和在用比例。
- 原始测量及接收机时钟字段、导航电文原始载荷独立保存。收到电文不等于已有完整可传播星历。
- 卫星页精确位置权限申请、60 秒真实采集、取消、本机原子存储；原始采集不进入 Android 备份。
- 采集器仅在场景停止时工作；模拟启动或收到 mock Location 会废弃采集，所有监听器在 finally 注销。
- 画像有效性检查：帧数、观测跨度、坐标、有效期、地平线。
- 星座比例采用累计该星座卫星样本数除以累计全部卫星样本数。置信区间用 10 秒时间块 bootstrap，短于三个块时返回完整区间，不将相邻帧当成独立伯努利样本。区间仅描述采集窗口，不能外推到其他地区、时段和设备。
- 统计回放使用实测帧的联合分布；正反向回放避免首尾跳变，跨北方向按最短圆弧插值。CN0 来自实测配对值，不使用人为正弦曲线。
- 核心模型支持 0 自动和正数卫星下限；只可从邻近实测帧补充真实身份，容量不足时记录诊断。已接入生产 runtime；App、Schema 和运行时默认值均为 0，保留已保存用户值。
- 几何 DOP 用局部 ENU 视线和各星座独立接收机钟差列，Householder QR 计算协方差。少于所需观测、秩不足或条件数过大时无解；W=I 为等方差几何 DOP，不把 CN0 当作未经标定的伪距方差。
- 带序列号的共享帧缓存，生产路径按接收秒、稳定路由与卫星下限隔离。全局、固定点、独立场景分别持有接收机帧，同一路由每秒首个样本锚定该秒的卫星状态、NMEA 和 extras；100ms 运动、海拔、速度及物理噪声更新不再反复创建卫星帧。
- 认证配置通道可下发有界压缩状态画像，压缩载荷限长且解压限量；原始测量/导航电文留在本机。

生产 GnssStatus、NMEA 和 GPS Location extras 已切换到接收机帧。旧固定 5 颗/31 颗模型、工厂、状态桥接器、配置枚举、运行时字段及 Schema 选择器已删除；旧偏好不再读取或下发，调试 API 对旧选择器返回明确错误。用户磁盘中已有的旧偏好不主动擦除，旧配置消息中的模型键不参与运行时选择。以上仅经 JVM 检查和 Kotlin 编译，尚不构成真机验收，完整目标仍未完成。

- [x] 状态和 NMEA 只保留主动投递；调用 ORIGIN 绕过真实回调抑制 Hook。NMEA 回调时间戳为帧 UTC 毫秒。

- [x] 注册在系统调用成功后入表，原始调用返回 false 或抛异常时不记录；注册时模拟关闭也安装回调 Hook，以支持后续开关。
- [x] 状态/NMEA 注册表按 Binder 去重、linkToDeath、显式注销和清理；覆盖 LocationManagerService 和 GnssManagerService NMEA 入口。
- [x] 主动投递读取每个监听器的固定点、独立场景及 deny 路由；Location extras 保留同一路由标识，真实状态/NMEA/raw 回调策略也按相同路由判断接收机帧是否可用。
- [x] 线程保存直接引用，停止时中断并有界等待，不再按线程名搜索；回调异常按监听器隔离并限频记录。
- [x] 最少卫星数设置为 0 自动、正数下限；当前 UI 与 Schema 均为 0–128，部分配置下发不重置已保存值。
- [x] 卫星页展示全部观测星座；Android CN0 0–63 dB-Hz 范围可进入画像，修复原有 60 上限导致有效观测被丢弃。

## 独立分布对照

Detector 的 JSON 报告新增 `gnssEvidence`，保存回调到达时间和逐信号卫星字段；非有限数值保留为字符串证据，不能让 JSON 序列化异常掩盖无效观测。报告没有自动证明数据来自真实接收机。先在已确认停止模拟的环境保存参考窗口，再采集模拟窗口；记录设备、位置、时段、接收环境、后端和实际最少卫星数设置。

独立脚本同时接受本机 `receiver-capture.json` 和新版 Detector 报告，不引用 Kotlin 模型或检测实现：

```sh
python scripts/compare_gnss_profiles.py receiver-capture.json detector-after.json --minimum-satellites 0 > comparison.json
```

每个 UTC 秒取最后一帧，避免同秒突发回调获得更大权重；数量、星座占比、在用比例按唯一星座/SVID 计算。在用身份取该卫星任一信号在用，不把多频计成多星。星座比例仍为累计该星座独立卫星样本数除以累计全部独立卫星样本数。报告可见数量与星座经验分布的总变差 `TV = ½ Σ |pᵢ − qᵢ|`，0 表示本次经验分布相同，1 表示互不重叠；还列出新增/缺失身份。逐信号联合直方图使用星座、5° 仰角箱和 5 dB-Hz CN0 箱，90° 纳入末个仰角箱。两边都保留原始逐信号证据时才报告该距离；频点覆盖变化也会改变该分布，不能单独据此判定模型失真。

均值和比例差采用两个窗口分别重采样的非重叠时间块 bootstrap，固定种子 0、1000 次，给出边际 2.5%–97.5% 百分位区间；默认块长 10 秒，可用 `--block-seconds` 改为其他长度检查敏感性。该方法假设窗口近似平稳、块间依赖较弱，默认块长不保证适合所有接收环境。共享同一画像的回放也不形成新的独立真实观测。每边不足 20 个接收秒、30 秒跨度、3 个块或完全没有卫星时不提供区间；采样空隙单独提示。

结果为描述性对照 `DESCRIPTIVE_ONLY`，不是来源真伪判定、统计等效性检验或自动验收 PASS。区间只描述这些窗口；包含零不能证明等效，多条边际区间也没有同时覆盖保证。正数卫星下限会主动改变分布，必须与自动模式分别评价。当前测试使用可解析的已知比例/计数/差异样本，尚无该设备的有效真实卫星窗口可据此完成分布验收。

- [x] 外部样本和场景使用原始单调时刻，在严格截止时刻失效；配置重复携带同一样本不会续期或误禁用，IPC 延迟不会重新激活运动。拒绝会溢出的样本截止时间，完整状态及会话标识加入日志脱敏。
- [ ] 运行中停用、路由/画像切换、并发旧上下文、噪声 seed 切换与多个路由的实际框架回调验收；JVM 检查不能证明 Binder 调度、厂商适配及进程重载恢复已通过。

`PreparedRuntimeConfigurationTest` 覆盖坏批次不发表、缺失/清除语义、完整解码、活动速度保留和合并最新样本；`ConfigCommandTest` 并发读取仅允许观察完整批次，`RuntimeSnapshotTest` 覆盖配置版本与样本并发。`SnapshotTest` 验证样本与一次发布的状态一致；`ProviderViewTest` 验证上下文、场景隔离和重复噪声视图。新增 ART 转换策略测试目前仅完成源码编译，尚未执行。

`RuntimeTransferWireTest` 与 `OrderedRuntimeReceiverTest` 覆盖完整状态往返、画像源复用、损坏/超限消息、陈旧样本、未来时刻及过期时钟；`SessionSequenceGateTest` 覆盖旧会话、重复/乱序、校验失败不推进及并发恢复。`LatestStateWorkerTest` 覆盖阻塞时一万次更新仅保留最新待发状态、关闭/失败清理及跨空闲间隔复用线程；`RuntimePeerRegistryTest` 用 Binder 替身验证容量、去重、死亡、慢连接隔离和替换竞态。这些测试未执行真实跨进程 Binder 事务，不能据此声称厂商服务重启、超时恢复、实际回调时序或高频传输性能已验收。

`RuntimeLifecycleTest` 覆盖完整恢复、停止/配置停用后的旧样本不复活、运动不续期和场景批次；`ControlCommandTest`、`LocationCommandTest`、`SampleCommandTest` 覆盖严格类型、算术、运动元数据及场景 ID 预校验。球面移动计算仅从状态对象抽离，继续沿用原有模型；它不替代 GNSS 的椭球观测几何或广播星历计算。

## GPS 星历实现与后续验收

GPS LNAV 的纯 Kotlin 数学和本机采集解码已落地，生产输出仍使用统计回放。位序/字校验按 Table 20-XIV，组帧要求同一卫星、同一个 30 秒发送帧和完整 IOD；扩展拟合期按 Table 20-XII，保留区间拒绝。完整周号由明确可信的 GPS 时刻解析，不硬编码 GPS−UTC 秒数；接收机时间采用整数/十进制先减偏差再转秒，避免绝对纳秒转 Double 丢精度。

原始采集新增时钟不确定度、漂移、闰秒证据、接收机事件单调时刻与回调到达时刻，兼容缺少这些字段的旧画像。GPS 捕获解码要求已知时间不确定度、附近一致且未重置的接收机时钟；回调到达时刻只用于周号/HOW 关联，不冒充精确发送时刻。缺证据、告警、陈旧、冲突或分页不完整时返回诊断，不由 hasEphemeris 标志推断星历。

GPS 组帧容量满时拒绝新候选，保留已有冲突记录直到采集显式结束/清空，防止缓存淘汰后重放消除冲突。每颗卫星只返回最新发送帧的完整结果；较新帧不完整、冲突或健康状态不可用时不回退旧健康结果。跨时钟重置或某卫星的新电文无法关联单调时钟时，采集解码撤回相关结果；包括重置发生在两个邻近关联窗口之间的情况。新增回归使用独立逐字奇偶重编码构造较新 HOW/不健康消息与冲突，并覆盖容量拒绝后的重放。

广播参数是为 ECEF 拟合的参数，不可将中间轨道坐标当成普通 ECI 再额外旋转。应包含 Δn、六个二次谐波项、IDOT、Ωdot 和 toe 地球自转项；GPS LNAV 的 μ=3.986005×10¹⁴，与通用二体试验常量不相同。计算发射时刻位置，并处理信号传播期间地球自转；钟差多项式、相对论项和 TGD 单独按对应观测信号处理。周跨越修正不能让陈旧一周的星历重新有效，须先以完整绝对时刻检查有效期。

GPS 接收几何通过有界真空光程方程求发射时刻，再将发射 ECEF 坐标旋转到接收时刻的 ECEF 轴。拟合期检查针对实际发射时刻；接收时刻稍晚于拟合期末但发射仍有效的情况可以成立。该模型不含电离层、对流层、天线和接收机偏差，不能据此生成伪距或载波相位。ENU 仰角采用与 asin(up/range) 等价且数值稳定的 atan2；天顶/天底方位角明确未定义，不制造数值。

Galileo、北斗 MEO/IGSO/GEO、GLONASS 必须分别核对接口规范和系统时标；不以 GPS 代码通过代替其他系统验证。每个解码器、每个传播器分别提交，使用独立权威导航向量和可追溯数值结果，补单元/时间/地平线/过期/分页切换等边界测试后才接生产路径。

## Galileo 星历基础与缺口

按 OS SIS ICD 2.2 实现独立完整 GST、GTRF 广播传播和双频参考钟差，I/NAV E1/E5b 与 F/NAV E1/E5a 参考显式区分。模型不把 GPS 与 GST 直接互换。解码器按 Galileo OS SDD 1.3 第 17 页与 Annex C.4.4.1 脚注 22，从解析后的完整 toe 建立 `0 ≤ t−toe ≤ 14400s` 年龄上限，附加独立限制只能缩短；这不是以 toe 为中心的 ±2 小时，也不证明服务状态未来四小时持续有效。BGD 和逐信号 SHS/DVS 独立保留，不能将数学轨道可计算等同于信号可用。

单频钟差已按 Tables 71/73 与 Eqs 18/19 接入独立计算器：I/NAV E1 减去 BGD(E1,E5b)，E5b 减去 `(1575.420/1207.140)² × BGD(E1,E5b)`；F/NAV E5a 减去 `(1575.420/1176.450)² × BGD(E1,E5a)`。不拿另一参考的 BGD 直接修正当前钟差，不从缺少该服务状态证据的消息推断可用信号。输入还需通过目标信号 SHS/DVS、SISA、BGD 字段范围和绝对有效期检查；双频参考钟差不额外减 BGD。测试以已有独立 C 钟差向量为基准，使用 Decimal128 和精确频率平方比 `5929/3481`、`23716/13225` 独立核对，不代表已有真机码伪距验证。

GPS 与 GST 之间已实现广播 GGTO 双向转换。GPS 周 1024 和 GST 周 0 的名义纪元对应不等于两种时标偏移为零。按 Eq. 24，`GST − GPS = A0G + A1G × (GST − t0G)`，正向必须求解隐式方程；相对名义 GPS 时刻的修正为 `(A0G + A1G × (GPS_aligned − t0G)) / (1 − A1G)`。反向在 GST 上直接计算多项式。系数保留有符号原始单位，比例分别为 2⁻³⁵ 和 2⁻⁵¹，不夹带 UTC 闰秒、接收机偏差或卫星钟差。两向结果按外部 GST 有效区间检查，不把 ±31 周的截断周解析规则当作有效期。

I/NAV word 10 与 F/NAV page 4 的 GGTO 解码器已落地。使用独立 GPS 证据解析 6 位 WN0G 对应的完整周号，避免先要求完整 GST 再转换 GPS 的循环依赖；仅在四个参数同时为全一时认定 GGTO 不可用，不因单个字段为全一而拒绝。调用方必须给出包含广播时间标签的 GPS 窗口，并计入发送端时钟不确定度，不能直接拿回调到达时刻代替。窗口最多 120 秒是关联策略，不是设备延迟保证；目前尚未建立 Android 采集证据到该窗口的适配。F/NAV 自带 TOW 必须落在窗口内，I/NAV word 10 不带时间戳，输出明确留空；解出的标签也不等于精确物理发射时刻。

转换使用 Decimal128 绝对时间仿射方程独立对照，覆盖正负系数、隐式分母、截断周边界、系统纪元边界与溢出。GPS/GST 时间加减和 GGTO 共用周内秒归一化，修复周边界负微小偏移舍入成 604800 导致异常，以及负次正规数除法下溢的问题；早于系统纪元的输入仍拒绝。合成 GGTO 页的位字段与 CRC 经固定版本 RTKLIB `getbits/getbitu/rtk_crc24q` C 函数核对，这只是字段提取和 CRC 对照，不是额外的独立 GGTO 周号解析器或时间转换实现。没有真实 GGTO 电文、发送窗口及有效期证据，不能据此宣称捕获时钟关联或物理天空输出完成。

Android I/NAV 采用 228 位偶/奇页组合，CRC 覆盖前 196 位，末尾 SSP 不在覆盖范围内；F/NAV 采用 214 位信息和 24 位 CRC。解码前核对载荷长度、填充位、页类型和 CRC24Q。I/NAV words 1–4 要求身份和 IOD 一致，word 5 独立提供 GST 与服务状态；F/NAV pages 1–4 核对共同 IOD、身份及相邻发送时刻。两者解析完整周号并拒绝 SISA 保留值与 NAPA。当前样本为真实 RINEX 参数独立重建的合成页，不是真机原始页。

采集窗口内的 I/NAV 与 F/NAV 组帧器已分别落地。调用方必须为每条输入提供可信的完整 GST，并明确给出采集窗口；完整解码后按 toe 应用 SDD 年龄上限，可额外提供更短的有效区间。最多 120 秒是组帧策略，不是星历拟合期，也不会由 UTC、GPS 周号或 hasEphemeris 推断。两者按卫星和 IOD 隔离，支持乱序；同一 IOD 的轨道/钟差/SISA 冲突会撤回结果，收齐后还须调用 completed() 复核晚到证据。每个组帧器最多保留 64 个候选，F/NAV 另限制 512 个不同发送页，不通过淘汰冲突来恢复输出。新的采集窗口使用新实例，不能拿一个实例持续跨窗口拼接。

按 ICD 5.1.9.2 区分 IOD 数据和独立更新的数据：I/NAV word 5 的 GST、BGD、逐信号健康/DVS 按卫星保存，最新 CED 批次不完整时不回退旧批次；F/NAV 使用最新发送的 page 1 服务证据，同样不回退到旧健康状态。BGD、健康、电离层或时标转换的正常更新不当作轨道冲突；相同发送时刻的服务内容冲突则拒绝输出。I/NAV 不带 GST 的 words 1–4 依赖调用方给出的可信采集时序选择批次，时序相同但 IOD 不同则报告歧义，不靠到达顺序决定。当前只在合成页上验证了这些规则，没有真机原始电文验收。

传播用四条同一 E24 卫星的真实记录，在两个钟差参考下对照 12 组固定 RTKLIB C 结果；覆盖范围不代表其他 Galileo 卫星已验收。CRC 用独立多项式长除法生成并经 RTKLIB C 校验；I/NAV 全参数另与 RTKLIB 解码器对照，F/NAV 参数按源 RINEX 和标准广播量化间隔核对，尚无独立 C 参数解码器对照。组帧测试覆盖全部收页排列、逐页冲突撤回、跨周/4096 周截断、健康/BGD 更新、容量上限和批次切换，组帧结果与完整页解码器对照；这些测试不构成额外的独立参数解码验证。OSNMA 认证、GGTO 真实采集/发送窗口及适用时段关联、真实坐标框架转换、生产天空输出与设备验收仍待完成。

### Galileo 接收几何与采集适配

接收几何显式接受 GTRF ECEF 接收机位置、局部椭球法线方向和接收 GST；不把 WGS 84 输入隐式改名为 GTRF。用轨道最大半径和接收机半径建立光程上界，在绝对有效区间内二分求解 `τ = range(tR−τ)/c`，然后将发射坐标按 `Rz(−Ωeτ)` 转入接收轴。单频入口在解出的发射时刻应用对应 SHS/DVS、SISA 和 BGD；不借此制造伪距、载波、CN0 或在用状态。

新增 12 组独立 RTKLIB C 接收向量，仍为同一 E24 的四条记录，涵盖三个显式合成接收原点/局部方向与多个时刻。C 用固定点迭代，Kotlin 用有界二分，比较光程、接收 ECEF、ENU、仰角、方位和双频参考钟差；单频再按精确频率平方比核对。`scripts/generate_galileo_reception_reference.py` 可从指定固定版本 RTKLIB 源码重建向量；这些输入不提供真实 GTRF/WGS 84 转换证据，微米级数值一致性也不代表广播轨道精度。

GPS 与 Galileo 采集共用已知不确定度和单调时钟关联，邻近距离按整数纳秒判断，避免长开机时间的 Double 舍入越过边界；纪元下溢返回诊断。`GalileoCaptureEphemerisDecoder` 要求独立建立且在适用时段内的 GGTO，随后从采集时钟得到近似完整 GST，供两个组帧器使用。缺少 GGTO 不走零偏移回退；跨时钟重置、超出 120 秒窗口拒绝拼接。某卫星/格式出现无法关联的新电文时撤回该格式的旧输出，不能恢复旧健康状态。当前只是带外部 GGTO 输入的本机解码能力，尚未从真实采集建立 GGTO 来源/适用时段，也未接生产天空。

本阶段 Core/NMEA/Xposed JVM 全套、App arm64 Kotlin 编译和模块规范检查通过。没有新安装、启动、重载或真机采集；生产仍为统计回放，完整目标未完成。

## 北斗传播基础与缺口

按 B1I 3.0 §§3.2/3.3、5.2.4.9/12 与 Table 5-11 实现独立 BDT、BDCS 轨道与无 TGD 的卫星钟差。MEO/IGSO 直接使用 BDCS 升交点公式；GEO 使用规范定义的中间惯性坐标、`Rx(−5°)` 和 `Rz(Ωe×tk)`。这里的矩阵符号按 ICD 的被动旋转约定，不能借用常见主动旋转公式而不换符号。使用北斗自己的地球自转常量 `7.2921150×10⁻⁵ rad/s` 和引力常量，轨道类型显式输入，不按历史 PRN 范围推断；因此支持输入现代 GEO 身份而不错误进入 MEO 分支。

12 组固定 RTKLIB C 数值来自明确标注的合成 B1I 参数，另有圆轨道 GEO 倾转解析检查、跨周连续性、陈旧整周拒绝和数值溢出回归。旧 RTKLIB 参考代码按 PRN 分支，生成脚本仅为选择参考方程映射 GEO→PRN1、IGSO/MEO→PRN6，Kotlin 测试仍保留实际输入的 SVID（包括 59）。这不验证 RTKLIB 的现代卫星分类，也不构成真实北斗电文或轨道精度验证。合成输入仅在测试资源，未加入生产卫星池。有效期仍要求独立证据，不把每小时更新/AODE 当作固定拟合期；D1/D2 页校验/参数解码/组帧、逐信号 TGD 和健康、接收几何/BDCS 接收机坐标、BDT 与其他时标转换、真实输入对照及生产天空尚待完成。
