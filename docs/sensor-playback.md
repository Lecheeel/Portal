# 传感器扩展与标准 Mock 优化

## 使用方式

日常使用 Xposed 后端即可启用应用传感器扩展，无需加载 Native。纯标准无 Root Mock 不具备改写其他应用传感器事件的权限。

1. 在框架中启用 Portal 的系统作用域。
2. 在「设置 → 应用传感器」选择目标应用，或输入完整包名。
3. 在框架作用域中同时勾选这些应用，并重新启动目标应用，包括其远程进程。
4. 启动场景；传感器跟随实际发布的速度、方向和海拔。固定点且没有移动输入时按静止处理。

默认目标列表为空。清空列表会关闭扩展；运行中撤销目标、停止场景或运动状态过期后恢复真实事件。配置和框架作用域需要同时满足，单独勾选其中一处不会启用模拟。

Native 仍可在后端页面手动启用。新安装保持标准 Mock 默认后端，Native 默认不启用；准备 Xposed 后端会主动关闭残留 Native 行为。已有偏好不会被批量重置。

## 覆盖范围

应用扩展处理 Android Java `SensorEventQueue`：加速度、磁场、陀螺仪、气压、重力、线性加速度、旋转向量、游戏旋转向量、地磁旋转向量，以及加速度/磁场/陀螺仪的未校准输出。未校准值与校准值使用一致的偏置关系。

步数和步伐检测按运动时钟生成，不依赖手机发生真实步伐。多个监听器共享一条模型时间线，并在应用原有回调 Looper 上分发；单独注销一个传感器不会影响其他注册项。累计步数使用已观测计数作为基线；恢复真实硬件后，其计数属于真实硬件时间线，不能保证与模拟累计值连续。

保留系统的传感器可用性和注册权限检查：缺少硬件或权限的传感器不会被凭空添加。原有采样率、批处理注册和 flush 路径仍由系统处理；模拟步伐按当前时间交付，不模拟硬件 FIFO 批处理。NDK、直接通道、厂商私有接口及其他传感器类型不在此扩展覆盖范围内。

模型使用单调时钟，重复或倒序采样不会重复累计步数。路线加减速、转弯、设备姿态、重力、线性加速度和四元数使用共同状态。步频随速度连续变化，波形和有界噪声按事件时间生成。

## 进程间状态与退出

目标应用只获得短期只读运动状态，不获得经纬度、完整配置或控制密钥。系统根据 Binder 调用 UID 查询实际包名并检查精确允许列表；共享 UID 的全部包都必须被选中。系统、隔离 UID 和未选中的应用不能使用此通道。

运动状态遵循分应用排除、场景路由和固定点路由。应用在工作线程上约每 250 ms 更新状态，单份授权最长 1 秒，且受源定位样本的 5 秒有效期限制。传感器回调不执行 Binder 查询；拒绝、停止、失联或过期后透传真实事件。注销最后一个受支持的监听器后退出工作线程，旧场景的待交付任务不能进入新场景。

Native 启用时不同时启用应用扩展。Native 帧独立按 50 Hz 更新，避免低频定位发布造成整段传感器波形被保持；停止会禁用行为，卸载已安装的 Native Hook 仍需重启。Native 步数使用整数联合体字段，避免把累计步数写成浮点数。其步伐检测仍依赖原有事件入口，不具备应用扩展的独立步伐分发能力。

## 标准 Mock 的调整

- 保留既有可选 GMS 通道、系统 Fused 通道和启动 burst。
- GPS、Network 和可选 Fused 使用实际配置的定位精度，并保留各 Provider 的相对精度差异。
- 成功停止所有模拟通道后，短期请求 GPS/Network 的新鲜真实定位；忽略模拟样本和早于请求时刻的缓存。新场景会取消旧请求，权限不足、Provider 关闭或超时会如实记录。
- 请求真实定位属于尽力恢复，不等于清除系统或其他应用的缓存，也不保证室内取得新定位。
- 无 Root 标准模式仍可能被系统重新加上 Mock 标记；发送端反射清除不代表接收端不可见。

新设置的卫星数量策略为「数量保证」，可见卫星下限为 59，模拟接收环境为「开阔天空」。这些是模拟天空的默认配置，不代表真实设备同时接收到 59 颗卫星；已有明确保存的偏好继续保留。

## 验证记录

2026-11-11，小米 M2102K1C，Android 14 / API 34，Vector API 102，使用独立检测应用 UID 验证应用传感器扩展：

- Native 未加载、未启用时，连续传感器正常产生约 100 Hz 数据；气压遵循硬件回调频率。
- 手机静止、模拟速度 1.5 m/s 时，6 秒窗口产生约 10–11 步；两个监听器收到相同的累计序列，没有因监听器数量增加而加倍。
- 单独注销步伐检测器后，其后续回调为 0，另一监听器及其他传感器继续工作；事件时间戳单调，回调保持在请求的线程。
- 运行中撤销目标及停止场景，均恢复真实磁场、气压和运动数据，模拟步数停止增长。
- 未选中时不能取得运动状态；选中后只返回最小运动字段，始终无法取得控制密钥。
- 校准和未校准三轴输出、重力及旋转向量已覆盖。Native 四种 ABI 通过编译和链接检查；本次未把 Native 的所有 ROM 行为视作已验收。

核心、主应用、Xposed 的 JVM 测试通过；模型测试覆盖时间顺序、步频、姿态关系、转向、授权到期与跨会话恢复。独立检测探针位于 detector 的 debug 源集中，不进入正式版本。
