# v1.7.0 界面设计与验证

参考本地项目中的交互思想，使用 Portal 原有 Android Views／Material 3 实现，不引入 Compose 或模糊渲染库，不复制参考项目源码。

| 参考 | 吸收的设计 | Portal 实现 |
|---|---|---|
| FakeGPS-next 路线库 | 搜索、独立空状态、清晰主次操作 | 三类标签、后台搜索、矢量空状态、导入导出菜单 |
| location-by-youself 状态组件 | 状态与播放操作集中、文字和坐标层级 | 单点卡片、运行概览、适配主题的状态颜色 |
| Kail Location 设置 | 类别分组、标题与说明分离 | 五组参数卡片、数值单独占行、保留所有设置入口 |
| GoGoGo／SSLAndriodTest | 地图为主、快捷操作 | 保留地图交互，增加触控区域和主题一致性 |
| HLocation 公开说明 | 状态源与界面分离 | 保留 Runtime 契约，仅在显示层降低样本重绘频率 |

## 性能边界

`RuntimePresentation.displayStates()` 将样本类变化限制为最多每 200ms 显示一次，生命周期、错误、后端、场景、能力和设定速度变化即时显示。后台定位服务不使用此显示过滤器，用户的提交间隔不变。所有收集使用页面生命周期，离开页面取消。

资料库每个 View 生命周期只有一个 `ListAdapter`。后台 `DiffUtil` 差量更新，不因 busy／消息更新重建适配器。搜索在 Default dispatcher 上执行、取消过期任务；可见列表复用条目，不为全部记录同时创建 View。动态列表不使用重排动画。

运行页收起详情时不格式化坐标／时间／能力长文本，日志只在事件或筛选变化时重绘。设置页只消费去重后的后端能力变化。首页对相同按钮文字避免重复赋值，降低样本更新触发的布局开销。

采用轻量矢量图、实色卡片和系统 ripple；不加入持续动画、模糊采样或位图装饰。

## 验证入口

`UiDesignTest` 覆盖连续样本压缩且终态即时传递、1000 条资料的 View 复用与点击身份、搜索与类别／导入菜单、浅色和深色主要页面截图。既有 `MapUiTest`、`SimulationFeaturesTest`、`RockerOverlayTest` 检查地图确认、章节重建、设置、诊断与悬浮速度操作。

截图由 Android API 35 CI 模拟器生成并上传 `ui-verification-*`，用于逐张检查排版；实际显示以最终提交的截图为准。JVM 测试与 lint／release 构建继续沿用现有 CI。没有用模拟器证据声称小米真机帧率、厂商保活或高德接受定位已验证。

截图前确认目标页面控件，等待窗口提交新帧及两次显示帧回调，避免把切页前画面当作验收结果。深色／浅色测试同时检查系统栏图标模式；横屏测试检查资料库装饰内容收起及返回竖屏后恢复。
